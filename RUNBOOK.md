# Runbook — guestbook

Инструкции для дежурного: что делать, когда сервис сломался.
Каждый шаг — готовая команда, выполнять по порядку.

**Секретов в документе нет.** Пароли лежат в `.env` на сервере, сюда их не копировать.

## Сервис не отвечает

Симптом: / или /health не отвечают, пользователи видят ошибки.

1. Жив ли сервис: curl -s http://localhost:8000/health
2. Запущены ли контейнеры: docker compose ps
   (app не running → docker compose up -d)
3. Что в логах: docker compose logs --tail=50 app
4. Доступна ли база: curl -s http://localhost:8000/db-check
5. Был недавно релиз? → откат: сменить тег образа на предыдущий
   В `compose.yaml` поменяй версию в строке `image:`, например:

   image: ghcr.io/ira-ivaa/guestbook-workshop:1.0.0

Затем:

    docker compose up -d
    curl -i http://localhost:8000/health

## Известные слабые места

- **Логи бедные.** На шаге 3 видны только стандартные строки uvicorn: нет ни контекста
  запросов, ни понятных сообщений об ошибках.
- **Метрик нет.** Нельзя посмотреть, когда начались проблемы, сколько было ошибок
  и как росло время ответа.
